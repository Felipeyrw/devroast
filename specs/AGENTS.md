# Specs

## Nomenclatura

`NNN-descricao-curta.md` — número sequencial com 3 dígitos, kebab-case.

## Estrutura de uma spec

1. **Título** — `# Spec NNN — Título descritivo`
2. **Contexto** — Por que existe, qual problema resolve
3. **Detalhamento** — Seções técnicas (tabelas, enums, fluxos, componentes, etc.)
4. **Queries/API de referência** — Como o frontend/backend consome
5. **To-Dos** — Checklist de implementação em ordem lógica
6. **Estrutura de arquivos** — Diagrama dos arquivos criados/modificados

## Regras

- Escrever a spec **antes** de implementar
- Usar markdown com tabelas, blocos de código e diagramas
- Referenciar screens/componentes do design quando aplicável
- To-Dos devem ser acionáveis e sequenciais
